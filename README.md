# depviz

Инструмент визуализации графа зависимостей для менеджера пакетов npm
(практическая работа №2, вариант №3, дисциплина «Конфигурационное
управление»).

## 1. Общее описание

`depviz` — консольное приложение, которое по имени и версии npm-пакета
строит граф его зависимостей и рисует его в виде изображения. Менеджеры
пакетов и сторонние библиотеки для получения зависимостей не
используются.

Приложение настраивается конфигурационным файлом в формате TOML.
Внешние зависимости не нужны: только стандартная библиотека Python
(для чтения TOML используется `tomllib`).

Статус работ:

| Этап | Содержание | Статус |
|------|------------|--------|
| 1 | Минимальный прототип с конфигурацией | выполнен |
| 2 | Сбор данных о прямых зависимостях | — |
| 3 | Основные операции (BFS, циклы, тестовый режим) | — |
| 4 | Дополнительные операции (порядок загрузки) | — |
| 5 | Визуализация (D2, PNG) | — |

### Что делает приложение на этапе 1

1. Читает конфигурационный файл TOML.
2. Проверяет каждый параметр и сообщает обо **всех** найденных ошибках
   сразу.
3. При успехе выводит все параметры в формате `ключ = значение`.

## 2. Описание функций и настроек

### Параметры конфигурации

Все параметры обязательны. Неизвестные параметры считаются ошибкой
(это помогает ловить опечатки).

| Параметр | Тип | Описание | Правила проверки |
|----------|-----|----------|------------------|
| `package_name` | строка | Имя анализируемого пакета | `test_mode = false`: допустимое имя npm (строчные буквы, цифры, `-._~`, возможен scope `@scope/name`, до 214 символов). `test_mode = true`: только большие латинские буквы (`A`, `B`, …) |
| `repository` | строка | URL репозитория или путь к файлу тестового репозитория | `test_mode = false`: абсолютный URL со схемой `http` или `https`. `test_mode = true`: путь к существующему файлу |
| `test_mode` | логическое | Режим работы с тестовым репозиторием | `true` или `false` (не строка и не число) |
| `version` | строка | Версия пакета | Формат SemVer: `1.2.3`, `1.0.0-beta.1`, `2.0.0+build.5` |
| `output_file` | строка | Имя файла с изображением графа | Расширение `.png`, непустое имя файла, каталог должен существовать |

Пример файла `config.toml`:

```toml
package_name = "express"
repository = "https://registry.npmjs.org"
test_mode = false
version = "4.18.2"
output_file = "graph.png"
```

### Аргументы командной строки

| Аргумент | Описание |
|----------|----------|
| `-c`, `--config ПУТЬ` | Путь к TOML-конфигурации (по умолчанию `config.toml`) |
| `--version` | Показать версию приложения |
| `-h`, `--help` | Справка |

### Коды завершения

| Код | Значение |
|-----|----------|
| 0 | Успех |
| 1 | Ошибка конфигурации (сообщения выводятся в stderr) |
| 2 | Неверные аргументы командной строки |

### Обработка ошибок

Обрабатываются: отсутствующий или нечитаемый файл, некорректный синтаксис
TOML, файл не в кодировке UTF-8, отсутствующие и неизвестные параметры,
неверные типы и значения всех пяти параметров. Traceback пользователю не
показывается.

### Структура репозитория

```
.
├── README.md
├── Makefile              # запуск, тесты, демонстрация ошибок
├── config.toml           # конфигурация по умолчанию
├── src/depviz/
│   ├── __main__.py       # python -m depviz
│   ├── cli.py            # аргументы, вывод, коды завершения
│   ├── config.py         # чтение TOML, объект Config
│   ├── validators.py     # проверки отдельных параметров
│   └── errors.py         # ConfigError
├── tests/                # модульные и сквозные тесты (unittest)
└── examples/
    ├── config_test_mode.toml
    ├── test_repo.txt     # файл тестового репозитория (формат — этап 3)
    └── invalid/          # конфигурации с ошибками для демонстрации
```

## 3. Сборка и запуск тестов

Требуется Python 3.11 или новее (проверено на 3.12) и `make`.
Сборка не требуется, зависимости не устанавливаются.

```bash
make test            # запустить все тесты
make run             # запустить с config.toml
make run CONFIG=examples/config_test_mode.toml
make demo-errors     # показать обработку ошибок на examples/invalid/
make clean           # удалить кэш Python
```

Без `make` (из корня репозитория):

```bash
PYTHONPATH=src python3 -m unittest discover -s tests -v
PYTHONPATH=src python3 -m depviz --config config.toml
```

## 4. Примеры использования

### Успешный запуск

```console
$ make run
package_name = "express"
repository = "https://registry.npmjs.org"
test_mode = false
version = "4.18.2"
output_file = "graph.png"
```

### Тестовый режим

```console
$ make run CONFIG=examples/config_test_mode.toml
package_name = "A"
repository = "examples/test_repo.txt"
test_mode = true
version = "1.0.0"
output_file = "graph.png"
```

### Ошибки конфигурации

Несколько ошибок в разных параметрах (`examples/invalid/bad_values.toml`):

```console
$ python3 -m depviz -c examples/invalid/bad_values.toml
Ошибка конфигурации:
  - package_name: недопустимое имя npm-пакета
  - repository: ожидается URL вида http://... или https://...
  - version: ожидается версия в формате SemVer, например 1.2.3
  - output_file: файл должен иметь расширение .png
$ echo $?
1
```

Неверные типы и неизвестный параметр
(`examples/invalid/wrong_types.toml`):

```console
Ошибка конфигурации:
  - неизвестный параметр: unknown_option
  - test_mode: ожидается логическое значение true или false
  - package_name: ожидается строка
```

Тестовый режим с несуществующими файлами
(`examples/invalid/bad_test_mode.toml`):

```console
Ошибка конфигурации:
  - repository: файл тестового репозитория не найден: examples/no_such_file.txt
  - version: ожидается версия в формате SemVer, например 1.2.3
  - output_file: каталог не существует: no_such_dir
```

Отсутствующий параметр, сломанный синтаксис и отсутствующий файл
конфигурации:

```console
Ошибка конфигурации:
  - output_file: обязательный параметр не задан

Ошибка конфигурации:
  - некорректный TOML в examples/invalid/broken_syntax.toml: Illegal character '\n' (at line 1, column 24)

Ошибка конфигурации:
  - файл конфигурации не найден: nope.toml
```
